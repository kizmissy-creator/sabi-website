# SABI friends sample round

Friends use the existing `/studio/` page and its original product dialogs. A valid invitation adds only an `Add sample` button to the product dialog, opening size and delivery fields in a second dialog. The page's existing design, story, descriptions and copy remain unchanged. Old `/studio/samples/#invite=…` links redirect to the original Studio page. The invitation is retained in tab-only sessionStorage so collection anchors and refreshes do not lose it; no delivery details are persisted in browser storage.

Both collections; one sample of each of the 11 products across all sizes; one successful request per invitation, with a second check against normalised email. Sam should send a different invitation to each person. No identity verification: someone with several invitations and different email addresses could bypass the person limit. Do not distribute the complete invitation file.

Local `.sample-private/SABI-sample-invitations.html` contains 11 friend links and a private organiser link. Original credentials are local only; only SHA-256 hashes are committed. Invitation fragments are not sent in page requests or referrers. JavaScript sends the token in POST JSON to the matching Netlify function. Neither addresses nor credentials are stored in localStorage or logs. The owner link can read delivery addresses; treat it as a password. Rotate a compromised credential by generating a new random 32-byte token and replacing its digest in `sample-access.mjs`, then redeploying (do not rerun the initial generator).

The request and owner functions use a site-scoped Netlify Blobs store `sabi-studio-samples-v1`, strong reads and conditional writes. All reservations for the round are committed in one object, so invite, email and product uniqueness are tested and written together. Conflicting writes retry against the latest object. A lost-response retry returns the original reference. No success is displayed before a confirmed durable write. Inventory survives new deploys. `friends-round` holds real requests; `test-round` holds synthetic tests independently. Test tokens cannot claim real stock.

There is no checkout, payment, supplier API order or automatic email. Sam opens the organiser, checks the garment/size, orders and pays through the supplier, then marks the request ordered or sent. Cancellation releases the product but keeps the invitation and email used. Cancellation does not cancel an already placed supplier order. Review and remove personal details after fulfilment and any necessary follow-up; Netlify administrators can manage the private store. Never paste addresses into GitHub issues or commits.

Ghost garment sizes are requested usual sizes, subject to confirmation; the UI must not imply all sizes or camouflage are available. Supplier mockups remain previews. All pages are noindex; only authenticated requests reveal claims or availability. The build copies only public website files to `dist`; source code, hashes, tests and local invitations are excluded. Keep the organiser link out of screenshots shared publicly.

Validation: `node --test tests/*.test.mjs`, `node scripts/build-site.mjs`, live synthetic request using test invitation, duplicate rejection, owner listing and mobile/desktop checks. Do not merge PR #3 as part of this preview work.
